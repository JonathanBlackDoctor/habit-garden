# 습관 정원 — 디자인 개편 핸드오프 패키지

외부 디자이너 / 외부 AI 에이전트에게 **앱 전체의 UX·UI를 한 번에 넘기기 위한** 묶음이다.

> ## ⚠️ 이 패키지는 전부 **개편 전(As-Is)** 자료다
> 여기 실린 화면·토큰·규칙은 **바꾸기 전 현재 상태**의 스냅샷이다. 제안이나 목업이 아니다.
> 새 디자인은 이 상태를 출발점으로 삼아 만든다. 캡처 시각과 커밋은 `screens/manifest.json`에 박혀 있다.

## 먼저 볼 것 — 실제 실행 화면

| | 내용 |
|---|---|
| **[`screens.html`](screens.html)** | **브라우저로 열면 41장의 실제 앱 화면이 한 페이지에 다 보인다.** 여기서 시작하라 |
| [`screens/`](screens/) | 원본 PNG 41장 (390×844 @2x) + `manifest.json`(캡처 시각·커밋·라벨) |
| [`capture-screens.mjs`](capture-screens.mjs) | 그 화면들을 다시 찍는 스크립트 — 앱이 바뀌면 재실행 |

캡처 방식: Firebase 에뮬레이터 + Vite dev 서버를 띄우고, **게스트 모드로 실제 로그인**해 Playwright가 라우트를 돌며 찍었다. 목업이 아니라 실행 결과다.

**이 세트의 한계 — 반드시 알고 볼 것**
- 게스트 계정이라 **데이터가 적은 초기 상태**다 (습관 3개 · 식물 1그루 · 200P).
- 습관 20개, 식물 24칸이 꽉 찬 **장기 사용자 화면은 없다.** 개편안은 그 밀도도 감당해야 한다.
- 에러·로딩·오프라인 상태는 담기지 않았다.

## 화면을 다시 찍는 법

```bash
pnpm install

# 터미널 1 — 에뮬레이터 (Java 필요)
npx firebase emulators:start --only auth,firestore --project planner-web-quick

# 터미널 2 — 개발 서버
cd apps/web && npx vite --port 5173 --host 127.0.0.1

# 터미널 3 — 캡처
node docs/design-handoff/capture-screens.mjs
```

`screens/`가 새로 채워지고 `manifest.json`의 캡처 시각이 갱신된다. 그 뒤 `screens.html`을 다시 생성하면 된다.

## 외부 에이전트에게 그대로 붙여넣을 킥오프 프롬프트

```
너는 모바일 PWA "습관 정원"의 UI/UX 리디자인을 맡은 프로덕트 디자이너다.

1) 먼저 docs/design-handoff/screens.html 을 열어 현재 앱 화면 41장을 전부 봐라.
   이건 개편 "전" 상태의 실제 실행 화면이다. 제안이 아니라 출발점이다.
2) 그다음 docs/design-handoff/ 의 문서 6종을 순서대로 읽어라.
   화면만 봐서는 알 수 없는 규칙·제약·금지사항이 거기 있다.
3) 06 문서의 "산출물" 항목대로 결과물을 만든다.
   착수 전 확인할 게 있으면 06의 "먼저 물어볼 것"을 참고해 한 번에 질문하라.

핵심 제약(요약, 자세한 건 05 참조):
- 모바일 온리. 셸 최대 480px, 기준 폭 380~412px. 데스크톱 레이아웃 없음.
- 라이트 모드 고정. 다크 모드는 이번 범위 밖.
- 한국어 UI. 한글 텍스트 길이를 전제로 레이아웃하라.
- Tailwind + shadcn/ui + Framer Motion + lucide-react 안에서 구현 가능해야 한다.
- 포인트/레벨/정원 성장 규칙 등 게임 경제 수치는 서버가 정한다. 표현만 바꾸고 규칙은 바꾸지 마라.

주의: 스크린샷은 게스트 계정의 초기 상태다. 습관 20개·식물 24칸이 찬
장기 사용자 화면은 세트에 없으니, 그 밀도를 별도로 상정하고 설계하라.
```
