# 06 · 개편 범위 & 산출물

> ⚠️ **이 문서의 "개편 목표"와 "우선순위"는 초안이다.** 발주자(owner)가 확정한 뒤 외부 에이전트에게 넘겨야 한다.
> 나머지 문서(01~05)는 코드에서 확인한 사실이므로 그대로 써도 된다.

## 개편 목표 — ✍️ 발주자가 채울 것

아래에서 해당하는 것을 고르고, 아닌 건 지운다. 목표가 흐리면 산출물도 흐려진다.

- [ ] **비주얼 리프레시** — IA·플로우는 그대로, 색·타이포·간격·카드만 다시
- [ ] **디자인 시스템 정비** — 03 문서의 "알려진 문제" 7개 해결이 주목적
- [ ] **화면 재설계** — 특정 화면(예: 오늘 탭, 정원)의 구조 자체를 다시
- [ ] **IA 개편** — 탭 구성·화면 배치까지 재검토
- [ ] **접근성·가독성 개선** — 11px 이하 텍스트 206곳, 터치 타깃, reduced-motion

한 줄 목표문:
```
(예시) "정원의 '살아 있는 것을 돌보는' 감정은 유지하되, 정보 밀도를 낮추고
       11px 이하 글자를 없애 40대도 편하게 읽을 수 있게 만든다."
```

## 화면 우선순위 (권장)

| 순위 | 화면 | 근거 |
|---|---|---|
| 1 | **오늘 `/`** | 매일 첫 화면. 위젯 12종 컨테이너 = 카드 시스템의 기준이 된다 |
| 2 | **습관 `/habits`** | 핵심 인터랙션(0~5점 체크). `HabitCard` 405줄 |
| 3 | **정원 `/garden`** | 감정적 핵심이자 최대 화면(855줄) |
| 4 | 공통 시스템 | 토큰 · 타이포 스케일 · 카드/버튼/헤더 패턴 |
| 5 | 플래너 `/planner` · 신앙 `/prayers` | 크지만 사용 빈도가 낮음 |
| 6 | 나머지 부속 화면 | 시스템이 정해지면 자동으로 따라온다 |

## 산출물 (이 형식으로 받는다)

이 저장소는 **HTML 목업을 디자인 원본으로 쓰는 관례**가 있다(`docs/04_목업_mockups.html`, `level_desigh/index.html`). 그대로 따른다.

### 필수

1. **`design-tokens-v2.json`** — 개편된 토큰. [`tokens.json`](tokens.json)과 같은 스키마.
   반드시 포함: 타이포 스케일(현행 임의 px값을 대체할 것) · 경고/주의 의미색 · 간격 스케일.
2. **화면 목업 HTML** — 우선순위 1~3의 화면. 브라우저에서 바로 열리는 자체 완결형 HTML.
   각 화면마다 **최소 3개 상태**를 그릴 것:
   - 빈 상태 (신규 사용자 — 오늘 탭 위젯 3개, 정원 빈 화단)
   - 일반 상태
   - 꽉 찬 상태 (위젯 12개 전부, 식물 24개, 습관 20개 이상)
3. **변경 근거 문서 1장** — 무엇을 왜 바꿨는지. 03 문서의 문제 7개 중 어떤 것을 해결했는지 매핑.

### 선택 (있으면 좋음)

4. 컴포넌트 스펙 — 카드·버튼·헤더·리스트행의 variant와 상태(default/hover/active/disabled/loading/error)
5. 모션 스펙 — 성장·레벨업·체크 애니메이션의 duration/easing
6. 구현 PR — 05 문서의 품질 게이트 3개 통과 시

### 받지 않는 것

- Figma 링크만 (저장소에 남지 않는다)
- 데스크톱 레이아웃
- 다크 모드 (범위 밖)
- 규칙·수치 변경 제안이 섞인 디자인 (05 문서 "절대 바꾸지 말 것")

## 수용 기준 체크리스트

개편안을 받으면 이 목록으로 검수한다.

**범위**
- [ ] 17개 화면 전부가 새 시스템으로 표현 가능한가 (목업이 없는 화면도 규칙으로 커버되는가)
- [ ] 탭 4개(신앙 OFF)와 5개(ON) 둘 다 성립하는가
- [ ] 오늘 탭이 위젯 3개일 때와 12개일 때 둘 다 성립하는가

**제약**
- [ ] 380px에서 가로 스크롤·잘림이 없는가
- [ ] safe-area(상단 노치·하단 제스처바)를 고려했는가
- [ ] 탭바 위 토스트 영역(72px)이 가려지지 않는가
- [ ] 좌우 스와이프 탭 전환과 충돌하는 제스처가 없는가
- [ ] Tailwind + shadcn + Framer Motion + lucide로 구현 가능한가 (새 의존성 없이)

**품질**
- [ ] 본문 최소 크기가 12px 이상인가 (현행 10~11px 대체)
- [ ] 터치 타깃 최소 44×44px인가
- [ ] 포인트(✦ bloom)와 샘물(💧 sky)이 시각적으로 명확히 구분되는가
- [ ] 시듦·실패 표현이 여전히 "나무라지 않는" 톤인가
- [ ] `prefers-reduced-motion`에서 정원 idle 애니메이션이 꺼지는가
- [ ] 텍스트 대비가 WCAG AA(4.5:1)를 넘는가 — 특히 `--fg-faint #9AA08F`

**일관성**
- [ ] 토큰 밖 색상 사용이 0에 수렴하는가 (현행 42곳)
- [ ] 임의 px 타이포가 스케일 토큰으로 대체됐는가 (현행 240여 곳)
- [ ] 30레벨 배지(`BloomBadge`)와 새 팔레트가 어울리는가

## 외부 에이전트가 착수 전에 물어야 할 것

에이전트에게 "아래 항목은 추측하지 말고 한 번에 물어보라"고 지시하는 목록이다.

1. 위 "개편 목표" 중 확정된 것은 무엇인가
2. 식물 SVG 아트를 다시 그리는가, 톤만 맞추는가
3. 탭 구성 변경을 검토 대상에 넣어도 되는가
4. 목업 3개 상태 중 우선순위가 있는가
5. 구현 PR까지 맡기는가, 디자인 산출물까지인가
6. 마감과 리뷰 라운드 수
