## 제한과 배포 전 확인

- 운영 계정과 운영 데이터를 사용하지 않았다. 실제 Google 로그인·운영 Telegram 동기화·운영 Cloud Functions 트리거 통합은 이번 단계에서 실행하지 않았다.
- 서버 집계 변경은 `dayScoreEngine` 선택 배포도 필요하다. 과거 기록 전체를 자동 재계산하거나 기존 스트릭을 소급 수정하지 않는다.
- 시작일 없는 기존 습관은 현재 활성 정의로 과거 대상 날짜를 계산한다. 보관·비활성 습관은 저장된 기록을 표시하며, 과거 반복 일정/활성 변경 이력이 없어 모든 과거 미기록 기회를 복원하지는 못한다. 반복 휴면은 기존 단일 휴면 구간 모델을 따른다.
- 주 N회 목표, 요일 일정, 다크 테마는 이번 구현 범위에 포함하지 않았다.
- 로컬 pnpm 11과 원본 lockfile/overrides 설정이 불일치해 frozen 설치가 실패했다. 기존 Habit Check backend의 검증용 node_modules를 디렉터리 junction으로 재사용했으며 lockfile과 의존성 선언은 변경하지 않았다. 배포 전 CI의 깨끗한 설치 검증이 필요하다.
- 개발용 `.env.development.local`만 demo-habit-week 로컬 프로젝트를 지정한다. 프로덕션 빌드는 추적 중인 공개 브라우저 설정으로 수행했다. 개인 인증정보는 복사·기록하지 않았다.

## 로컬 실행

`http://127.0.0.1:18744/habit-garden/#/?view=week`

개발 서버는 apps/web에서 `node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 18744 --strictPort`로 실행한다. Auth 9099, Firestore 8080은 운영과 분리된 `demo-habit-week` 프로젝트의 로컬 에뮬레이터다. 사용자 화면 캡처에는 가상 데이터만 사용했다.
